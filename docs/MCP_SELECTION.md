# Выбор Excel MCP Server

Выбран **Excel MCP Server 2.3.2** проекта Haris Musa, лицензия MIT. Релиз опубликован в PyPI. Сервер создаёт и редактирует настоящие книги Excel, использует сохранение через временный файл с атомарной заменой и поддерживает stdio и Streamable HTTP. Проверены Python 3.12, Python MCP 2.3.0 и TypeScript SDK `@modelcontextprotocol/sdk` 1.32.2. [Репозиторий](https://github.com/haris-musa/excel-mcp-server) · [Релиз 2.3.2](https://pypi.org/project/excel-mcp-server/2.3.2/) · [Лицензия](https://github.com/haris-musa/excel-mcp-server/blob/main/LICENSE)

В локальном запуске `initialize` и `tools/list` вернули 26 инструментов в настроенных группах. Полные схемы доступны через `npm run mcp:tools`. Проверены Unicode-имя листа «Заявки», создание, запись текста на русском и чтение после повторного подключения.

## Критерии выбора

| Требование проекта | Что подтвердило выбор |
|---|---|
| Готовый сервер для локального Excel | Сервер установлен из PyPI и запущен отдельным процессом через stdio. Каталог запрошен у работающего процесса |
| Создание, чтение и изменение `.xlsx` | Сервер создал книгу с листом «Заявки». В интеграционной проверке он записал строку №104 и обновил только ячейку D5 |
| Сохранение результата | Новый MCP-клиент после переподключения прочитал обновлённый статус, остальные ячейки совпали |
| Ограничение области доступа | Параметр `--allow-dir` задан на папку `data`. Клиент приложения передаёт фиксированное имя книги и разрешённые операции |
| Удалённое подключение в будущем | Проверен Streamable HTTP на локальном адресе. Сервер вернул 401 без токена, с токеном каталог и чтение прошли |

Поддержка HTTP оставляет путь к будущему развёртыванию. Для локальной разработки достаточно stdio и установленного Python-сервера. [Отчёт об операциях с реальным MCP](TEST_REPORT.md)

## Инструменты в проекте

| Инструмент | Параметры приложения | Назначение |
|---|---|---|
| `describe_sheet` | `path`, `sheet` | Определяет границы данных |
| `read_range` | `path`, `sheet`, `range`, `max_cells` | Возвращает строки, включая контрольное чтение |
| `write_range` | `path`, `sheet`, `at`, `rows` | Добавляет строку или меняет одну ячейку статуса |
| `describe_workbook` | `path` | Проверяет книгу при инициализации и сбросе |
| `create_workbook` | `path`, `sheets`, `overwrite: false` | Создаёт демонстрационную книгу |
| `format_range` | `path`, `sheet`, `range`, `style` | Оформляет шапку |
| `set_sheet_layout` | `path`, `sheet`, `layout` | Задаёт ширину столбцов, цвет вкладки и закрепление шапки |

`clear_range` присутствует в поставляемом каталоге. Сброс использует один `write_range` с исходными строками и пустыми значениями для добавленных ячеек. Поиск по точному номеру, имени и статусу выполняется по снимку `read_range`. [Схемы инструментов сервера](https://github.com/haris-musa/excel-mcp-server/blob/main/TOOLS.md)

## Подключение

```bash
.venv/bin/excel-mcp-server stdio --allow-dir "$PWD/data" --tools workbooks,data,formatting,sheets
```

Каталог `data` ограничивает путь на стороне сервера. Приложение подставляет относительное имя `requests.xlsx` и пропускает только известные инструменты. Настройка `MCP_MODE=http` переключает транспорт, сохраняя те же вызовы. Внешней сети требуются HTTPS и Bearer-токен. [Настройки транспорта и доступа](https://github.com/haris-musa/excel-mcp-server#remote-use-streamable-http)

Атомарное сохранение защищает книгу от частично записанного файла. Для цепочки «прочитать → вычислить ID → записать» приложение дополнительно сериализует операции своего процесса. Для нескольких реплик или внешних редакторов нужен общий механизм координации.
